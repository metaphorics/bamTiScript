## E3.3 contract and mutation

### Public contract

- `emit_reproducible` emits the same inputs twice and returns a `ReproducibleArtifact` only when the two object byte streams are byte-identical.
- `BuildCacheKey` canonicalizes every input that can change the emitted bytes: the canonical source program hash, the resolved target fingerprint, the normalized object metadata, and the object bytes hash. Any change in source or target changes the key.
- `canonical_object_metadata` sorts the undefined helper symbol list and normalizes all recorded object fields before hashing, so symbol order and metadata cannot alter identity.
- The build path and timestamp inputs are fixed: the object file symbol is `REPRODUCIBLE_FILE_NAME` (`"bamts"`) and the object writer does not embed wall-clock time.

### Focused tests

- `identical_inputs_emit_identical_bytes_and_keys`
- `changed_source_changes_cache_key_and_bytes`
- `canonical_metadata_sorts_helper_symbols`
- `target_fingerprint_is_part_of_cache_key`

### Registered mutation

| Field | Value |
|---|---|
| Name | `omit-source-hash` |
| Target | Replace `BuildCacheKey::source_hash` with a zeroed `[u8; 32]` digest (`[0; 32]`) so the canonical source program is no longer part of the cache key. |
| Effect | Two different source programs that happen to produce the same emitted object metadata and object bytes will collide in the cache. The focused test `changed_source_changes_cache_key_and_bytes` fails, and `emit_reproducible` can no longer guarantee that changed semantic inputs do not collide. |
