## Current scoped source status (2026-08-27)

- `MergeTable::declare` is total and always returns a real `SymbolId`; it has no augmentation sentinel branch.
- `declare_in_module` resolves a registered target module, then applies normal declaration merging inside that module. An augmentation may add a new exported name; TypeScript 7.0.2 does not require an existing same-name binding.
- Missing or incompatible target-module diagnostics belong to the production module-resolution/checker boundary. This model has no production caller and must not invent a name-level `INVALID_AUGMENTATION_BINDING` diagnostic.
- `augmentation_declares_into_the_target_module_scope` pins the valid new-binding behavior. Cycle and merge tests cover the model's remaining contract.
- Binder diagnostics use `AUGMENTATION_CYCLE` (`BAMTS-C082`), `EXPORT_CYCLE` (`BAMTS-C083`), and `EXPORT_AMBIGUOUS` (`BAMTS-C084`). `BAMTS-C024` is `BARE_SUPER_EXPRESSION`; it is unrelated to augmentation binding.

G1–G6 remain unchecked because their declared completion-framework, receipt, coverage, regression, mutation, and full leaf-gate commands were not run by this scoped repair.
